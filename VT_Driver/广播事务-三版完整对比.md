# 广播事务三版完整对比

## 版本定义

- **V1 原版**：`F:\001\VT\UnrealVTDbg1`
  - Guest 侧单文件 `DbgkSysWin10/11\Hvm\hypervisor_gateway.cpp`
  - Hypervisor 侧单文件 `VT_Driver\vmcall_handler.cpp`
- **V2 739937f**：`GG-Boy223/UnrealVTDbg-New` 分支 `Intel-VT`，提交 `739937f`
  - Guest 侧拆分 4 文件（`HypervisorGatewayApi/Broadcast/BroadcastSupport/Internal`）
  - 该提交「全量删除广播事务」
- **V3 当前**：`F:\001\VT\Intel-VT`（本仓库）
  - 文件结构与 V2 相同
  - 目前只删了 `broadcast_vmcall` 一处事务，其余事务仍残留

## 五、Hypervisor 侧分发对比（V1 vs V2/V3）

（V2 739937f 未改动 hypervisor 侧，所以 V2 与 V3 的 hypervisor 侧相同，只需和 V1 比。）

| 项 | V1 原版 | V2/V3 当前 |
|---|---|---|
| 结构 | 单 switch | `ReadRequest` + `ArePreconditionsValid` + `Execute*` + 主 switch |
| 前置校验 | 无 | 有 `ArePreconditionsValid` |
| MTF 收敛 | 无 | 入口先收 `mtf_pending` |
| hook/unhook | 只改当前 `*vcpu->ept_state` | 只改当前 `*vcpu->ept_state`（同） |
| 断点缓冲 / fake page 读 | 无对应跨核循环 | `for vcpu[i].ept_state` 跨核遍历 |
| 新增命令 | 无 | `PEEK_BREAKPOINT` / `CLEAR_BREAKPOINT_STATE` / `SYNC_CR3_EXIT_POLICY` / `SET/GET_SOFTWARE_BREAKPOINT_BUFFER` |

## 六、结论

- V2（739937f）= 原版「每核 N 次」广播模型 + `SafeVmCall` 等安全包装 + 独立参数结构 + CR3 同步。
- V3（当前）目前只把 `broadcast_vmcall` 和 `VmcallBroadcastArgs` 对齐到 V2，其余 7 处事务 + 回滚机制还没删，属于「半对齐」状态。
