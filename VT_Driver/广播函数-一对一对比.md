# 广播函数一对一对比：原版 / 本项目 / 其他项目

> 本项目 = `F:\001\VT\Intel-VT`（当前，已删广播事务后的状态）。
> 原版 = `F:\001\VT\UnrealVTDbg1`。
> 其他项目 = `F:\001\VT\中间目录` 下的 HyperDbg / HvVmxCore / Ophion。

## 1. broadcast_vmoff（全核 VMXOFF）

- 原版：`__vm_call(VMCALL_VMXOFF,0,0,0)` + `KeSignalCallDpcSynchronize` + `KeSignalCallDpcDone`；由 `vmoff()` 用 `KeGenericCallDpc` 广播。
- 本项目：`SafeVmCall(VMCALL_VMXOFF,0,0,0)` + `SignalDpcDone`；由 `vmoff()` 用 `KeGenericCallDpc` 广播。差异：只把裸 `__vm_call` 换成 `SafeVmCall`。
- 其他项目：
  - HyperDbg：`Vmx.c:1155` `PlatformDpcGenericCall(DpcRoutineTerminateGuest)` → 每核 `DpcRoutineTerminateGuest` → `VmxTerminate()`（DPC 广播，root 模式直接 VMXOFF，不走 VMCALL）。
  - HvVmxCore：`VmxSetup.cpp:999` `for` 遍历核 + `KeSetSystemAffinityThreadEx(1<<i)` 逐核 VMXOFF + `VmxOffDone` 确认。
  - Ophion：`broadcast_terminate_all()` = `KeGenericCallDpc(dpc_terminate_guest)`。

## 2. broadcast_invept_all_contexts / broadcast_invept_single_context

- 原版：`__vm_call(VMCALL_INVEPT_CONTEXT, true/false, 0, 0)` + sync/done；`invept(bool)` 用 `KeGenericCallDpc` 广播。
- 本项目：`SafeVmCall(VMCALL_INVEPT_CONTEXT, true/false, 0, 0)` + `SignalDpcDone`；`invept(bool)` 用 `KeGenericCallDpc`。差异：仅 SafeVmCall。
- 其他项目：
  - HyperDbg：不在 guest 发 VMCALL，而是 hypervisor 侧 `EptInveptSingleContext(本核EPTP)` / `EptInveptAllContexts()`；跨核用 **NMI 广播** `VmFuncNmiBroadcastInvalidateEptSingleContext/AllContexts`（`Export.c:726-772`）。
  - HvVmxCore：`VmExitHandler.cpp:299-303` 直接 `__invept(InveptAllContext)`。
  - Ophion：`ept_invept_single` / `ept_invept_all`（直接 `asm_invept`，无广播包装）。

## 3. broadcast_read_ept_fake_page_memory

- 原版：`__vm_call_ex(VMCALL_READ_EPT_FAKE_PAGE_MEMORY, target, proxy, origin, cr3, 0×5)`；复用 `HookFunctionArgs`（proxy/origin 被当 buffer/size 双关）。
- 本项目：`SafeVmCallEx(VMCALL_READ_EPT_FAKE_PAGE_MEMORY, target, buffer, buffer_size, cr3, 0×5)`；用独立 `SoftwareBreakpointBufferArgs`；每核直发。
- 其他项目：
  - HyperDbg：对应读 fake page 在 hypervisor 侧 `EptHook.c` 遍历 `g_GuestState[i]` 完成，不是 guest 广播。
  - HvVmxCore：无独立 read-fake-page 广播，在 `VmExitHandler.cpp` 的 EPT violation 里处理。
  - Ophion：无（skeleton）。

## 4. broadcast_get_hide_software_breakpoint / broadcast_set_hide_software_breakpoint

- 原版：`get_hide_software_breakpoint` / `set_hide_software_breakpoint` → `__vm_call_ex(VMCALL_READ_SOFTWARE_BREAKPOINT / VMCALL_HIDE_SOFTWARE_BREAKPOINT)`；复用 `HookFunctionArgs`。
- 本项目：改名为 `broadcast_get_software_breakpoint_buffer` / `broadcast_set_software_breakpoint_buffer`（`VMCALL_GET/SET_SOFTWARE_BREAKPOINT_BUFFER`）；用 `SoftwareBreakpointBufferArgs`；每核直发。API 层 `get_hide_software_breakpoint` / `set_hide_software_breakpoint` 变成包装函数，最终调用 buffer 版本。
- 其他项目：
  - HyperDbg：在 hypervisor 侧处理（无 guest 广播）。
  - HvVmxCore：无对应（隐藏断点逻辑并入 hook）。
  - Ophion：无。
- 注意：`VT_Driver\HypervisorGateway\hypervisor_gateway.cpp`（hypervisor 侧旧网关）仍保留 `broadcast_get_hide_software_breakpoint` / `broadcast_set_hide_software_breakpoint` 旧名和 `VMCALL_READ_SOFTWARE_BREAKPOINT / VMCALL_HIDE_SOFTWARE_BREAKPOINT`。

## 5. broadcast_hook_function / broadcast_unhook_function

- 原版：hook 用 `VMCALL_EPT_RIP_HOOK`，unhook 用 `VMCALL_EPT_UNHOOK_FUNCTION`；每核 `__vm_call_ex` / `__vm_call`。
- 本项目：hook 用 `VMCALL_EPT_RIP_HOOK`，unhook 用 `VMCALL_EPT_UNHOOK_FUNCTION`；每核 `SafeVmCallEx` / `SafeVmCall`；已删 `committed_processors` 记录和 `broadcast_rollback_hook_function`。
- 其他项目：
  - HyperDbg：hypervisor 侧 `EptHook.c` `for` 遍历 `g_GuestState[i].EptPageTable` 改表，然后 `EptInveptSingleContext(VCpu->EptPointer)`。
  - HvVmxCore：guest 侧 `DriverEntry.cpp:110-129` `KeSetSystemAffinityThreadEx(1<<i)` 逐核 `AsmVmxVmcall(VMCALL_EPT_HOOK / VMCALL_EPT_UNHOOK)`。
  - Ophion：skeleton，未实现。

## 6. broadcast_vmcall

- 原版：`__vm_call(vmcallinfo->command, vmcallinfo, 0, 0)`；API `vmcall(PVOID)` 单参数。
- 本项目：`TryReadVmcallCommand` 安全读 command → `SafeVmCall(command, vmcallinfo, p2, p3)`；API `vmcall(PVOID, p2, p3)` 三参数；每核直发（已删 `IsEptMutation` 单核属主事务）。
- 其他项目：
  - HyperDbg：用户态只向一个核发 VMCALL，`Vmcall.c` 在 hypervisor 侧处理，必要时内部跨核；不做 guest 侧 N 核广播。
  - HvVmxCore：用 `AsmVmxVmcall(VMCALL_EPT_HOOK, ...)` 逐核（亲和性 pin）。
  - Ophion：无通用 vmcall 广播。

## 7. broadcast_test_vmcall

- 原版：`__vm_call(VMCALL_TEST,0,0,0)` + statuses++；`test_vmcall()` 用 `KeGenericCallDpc`。
- 本项目：`SafeVmCall(VMCALL_TEST,0,0,0)` + statuses++；`test_vmcall()` 用 `KeGenericCallDpc`。差异：仅 SafeVmCall。
- 其他项目：
  - HyperDbg：有 `NMI_BROADCAST_ACTION_TEST`（压力测试广播），不是 test_vmcall 概念。
  - HvVmxCore：无 test_vmcall（有 `VmxMeasureTcs` 等）。
  - Ophion：无。

## 结论（广播机制归纳）

| 项目 | 广播机制 | INVEPT 方式 | hook 改表方式 |
|---|---|---|---|
| 原版 UnrealVTDbg1 | guest 侧 `KeGenericCallDpc` → 每核 `__vm_call` | 每核 `VMCALL_INVEPT_CONTEXT` | 每核改自己 EPT |
| 本项目 Intel-VT | guest 侧 `KeGenericCallDpc` → 每核 `SafeVmCall` | 每核 `VMCALL_INVEPT_CONTEXT` | 每核改自己 EPT |
| HyperDbg | 无 guest 广播；hypervisor 侧遍历所有核 + NMI 广播 | 每核 `EptInveptSingleContext`（各自 EPTP） | hypervisor 侧遍历 `g_GuestState[i]` 改所有核 |
| HvVmxCore | guest 侧 `KeSetSystemAffinityThreadEx` 逐核 pin + `AsmVmxVmcall` | `__invept(InveptAllContext)` | 每核改自己 EPT |
| Ophion | `KeGenericCallDpc`（仅 init/terminate） | `ept_invept_single/all` 直调 | skeleton，未实现 |
