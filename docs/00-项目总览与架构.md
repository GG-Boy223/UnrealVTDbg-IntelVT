# 00 项目总览与架构

本文档由逐行代码扫描整理。Delphi GUI 仅做逻辑理解，未做修改。

## 1 项目定位

- 目标：自建 Intel VT-x 调试器，可被 CE、x64dbg、x32dbg 直接调试。
- 能力：EPT 无痕 Hook、INT3 软件断点隐藏（伪页）、地址访问监控（读、写、执行）、CR3 跟踪、调试事件接管。
- 不含：硬件断点（DRx）。

## 2 目录与职责

| 目录 | 职责 |
| --- | --- |
| VT_Driver | VMX root 态核心：VMXON/VMLAUNCH、VMCS 填充、EPT 构建与 Hook/Watch、VM-exit 分发、Host 页表、CR3 跟踪 |
| DbgkSysWin10 | Win10 22H2 guest 态调试子系统（与 Win11 版本独立维护） |
| DbgkSysWin11 | Win11 21H2 至 25H2 guest 态调试子系统（独立维护） |
| Common/Ring0 | 公共库：串口日志、PDB 符号解析、PCI、Blowfish、生命周期策略 |
| Common/Shared | DriverProtocol.h 等共享协议与错误码 |
| Hook | 用户态 Hook 侧：Nt 调试 API 前置处理与状态清理 |
| Loader、UnrealDbg、UnrealDbgDll、CardRegistration、D-encryption | 装载器、Delphi GUI、授权与加密 |

## 3 关键调用通道

1. guest 态驱动（DbgkSysWin10/11）调用 hvgt 网关（Hvm/hypervisor_gateway.h）。
2. 网关执行 VMCALL，产生 VM-exit（reason 18）。
3. VT_Driver 的 VmCall/VmcallDispatch.cpp 在 root 态处理并回填结果。

由此得出一个重要结论：EPT Hook 安装、watch 安装与卸载、断点残留状态清理都在 root 态完成，root 态不会去等待 guest 态持有的锁。

## 4 必须保持的不变量

1. 共享可变状态（eptWatchList、Cr3Tracker、MTF pending 等）只在 root 态访问。已核对 eptWatchList_lock 的全部加锁点，均位于 VM-exit 处理与 VMCALL 处理两条路径。
2. 进入 root 态后不引用 guest 页表；Host CR3 与 Host 页表由 Globals/HostTables.cpp 构建。
3. VM-entry 失败、未处理 EPT violation 超限、释放活跃上下文统一走 vmx_fatal_error 到 KeBugCheckEx，属 fail-fast 设计。

## 5 平台范围

- CPU：Intel 8 至 14 代、X 系列、Ultra 全系、Xeon E 系列，统一路径处理。
- 系统：Win10 22H2；Win11 21H2、22H2、23H2、24H2、25H2。
- 单路 CPU，逻辑处理器不超过 64。
- 不额外增加进入 VT 的门槛；能力差异由 VmcsControls.cpp 的 ajdust_controls 自动收敛。
